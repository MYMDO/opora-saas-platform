# ADR 0001: Півот на конфігуровану SaaS-платформу

- Статус: прийнято
- Дата: 2026-08-23
- Джерело: `docs/blueprint/saas-platform-blueprint.md`

## Контекст

ОПОРА v1 (вертикальний B2B SaaS: ШІ-агенти, EMS, Фінанси) побудована як hand-coded
SPA + Workers/D1. Отримано блюпринт конфігурованої платформи (Builder/Runtime,
metadata control plane, JSON DSL) і ухвалено рішення зробити його основою проєкту.

## Рішення

1. **Повний pivot**: нова кодова база будується за блюпринтом; поточна реалізація
   ОПОРА v1 архівується в `reference/opora-v1/` як заморожений референс
   (читати можна, розширювати ні).
2. **Дані — гібрид через порт**: MVP працює на D1 (Cloudflare Free, $0),
   але `data-runtime` будується за interface-портом, щоб PostgreSQL+RLS
   підключався без переписування споживачів. RLS «остання лінія» з блюпринта
   замінюється на app-level tenancy до появи PG; межа орендаря тестується.
3. **Монорепо одразу**: pnpm workspaces + Turborepo, структура `apps/*`,
   `packages/*` за §7 блюпринта.

## Наслідки

- Next.js відкладено: SPA/Pages лишається стратегією фронтенду до потреб SSR.
- BullMQ/Redis не використовується у MVP: черги з'являться після CRUD
  (Cloudflare Queues або managed) — outbox-патерн проєктуємо з першого дня.
- Доменні знання ОПОРИ (КМУ №692/1048, тарифи НКРЕКП) зберігають цінність:
  ОПОРА-модулі стануть першими конфгурованими застосунками платформи після MVP.
- Всі майбутні задачі агентам формулювати за §11: вузькі контракти,
  заборонені області, критерій готовності.
